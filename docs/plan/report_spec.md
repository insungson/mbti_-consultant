## 1. 리포트의 역할

- 기획기반문서 2장 ② 레이어: **"알아봐 주는" 경험으로 신뢰를 만든다.**
- 각 섹션 끝에서 ③ AI 페르소나 상담으로 자연스럽게 이어 준다.
- 모바일 100%: 한 섹션은 한두 화면 안에서 끝나도록 짧게 쓴다.

## 3. 섹션 상세

### 3.1 유형 요약 — 거울 카피 (`mirror`)
- **목적**: 첫 화면에서 "이게 바로 나구나"를 느끼게 한다. 리포트 전체에서 가장 중요한 첫인상이다.
- **구성**
  - `headline`: 한 줄, 25자 안팎
  - `lines`: 3~4문장, 문장당 60자 이내
  - 마지막 문장은 오해받기 쉬운 부분을 풀어 주는 **인정 문장**으로 끝낸다.
- **규칙**: 톤 가이드 §2 공식(장면 + 속마음 + 인정). 각 문장이 정반대 유형에게는 어색해야 한다(고유성).

### 3.2 성향 지표 (부가)
- **데이터**: 검사 결과의 축별 `pole`과 `percentage`
  - `scoring.json`: 강도 = |합계| ÷ 45 × 100, 0~100
- **화면 표기**: 강도를 양극 비율로 바꿔 보여 준다.
  - 우세 쪽 = **50 + 강도 ÷ 2** (반올림)
  - 예: 내향 강도 44 → "내향형 72% · 외향형 28%"
- **축 설명**: 양 끝 모두 장점으로 한 줄씩 쓴다. 우열이 없어야 한다.

  | 축 | 한쪽 | 반대쪽 |
  |---|---|---|
  | 에너지 | 외향형: 사람들과 어울리며 에너지를 채우는 편이에요 | 내향형: 혼자만의 시간에 에너지를 채우는 편이에요 |
  | 인식 | 감각형: 지금 눈앞의 사실과 경험을 믿는 편이에요 | 직관형: 숨은 의미와 앞으로의 가능성에 끌리는 편이에요 |
  | 판단 | 사고형: 원칙과 논리로 공정하게 판단하려는 편이에요 | 감정형: 사람과 가치를 먼저 살피며 판단하는 편이에요 |
  | 생활 | 판단형: 계획을 세우고 정리된 상태에서 편안한 편이에요 | 인식형: 열어 두고 상황에 맞춰 움직일 때 편안한 편이에요 |

- **A/T(안정형/민감형)**: `scoring.json`의 `turbulence.enabled`가 `false`라 **미구현**이다. 지금은 4개 축만 표시하고, A/T는 데이터가 생기면 추가한다.
- **미결**: 축 합계가 0일 때 어느 쪽으로 판정할지 규칙이 없다 → 유저 플로우(단기 ④) 채점 설계에서 정한다.

### 3.3 인구 비율 (부가)
- 표기: "전체의 약 {n}%로 추정돼요" + 작은 글씨 "참고용 추정치"
- 금지: "희귀한", "특별한 소수", "흔한" 같은 우열 암시

### 3.4 핵심 강점 (`strengths`)
- 기존 5개를 유지하고 `description`을 해요체로 다시 쓴다.
  - 인지기능 약어는 뺀다.
  - 문형은 "~해서 ~할 때 특히 빛나요".
- `title`은 명사형 그대로 두되, 딱딱한 한자어는 풀어 쓴다(예: "탁월한 조직력" → "판을 짜는 힘").

### 3.5 이럴 땐 조금 지칠 수 있어요 (`weaknesses`)
- 기존 4~5개를 유지한다.
  - `title`: 상황형("~할 때")으로 바꾼다.
  - `description`: 강점의 그림자로 다시 쓴다.
  - **신규** `recovery`: 회복 실마리 한 줄을 붙인다.
- 낙인 단어(결함·문제·부족·미발달·둔감·통제 욕구 등)는 쓰지 않는다.

### 3.6 직업 (`careers`)
- **신규** `workStyle`: 일하는 방식·강점이 빛나는 환경 3문장. 기획기반문서 7장 "어울리는 일하는 방식·강점이 빛나는 환경"에 해당한다.
- `recommended`: 기존 분야·직무를 그대로 쓴다. `reason`은 해요체로 다듬는다.
- `lessIdeal`: "에너지가 많이 들 수 있는 환경"이라는 제목 아래 **직업명을 쓰지 않는다**.
  - 기존 `field`(예: "예술/디자인", "금융 및 회계")를 환경 라벨 `environment`로 바꾼다(예: "잘한 기준이 개인 취향뿐인 일").
  - `reason`도 환경 중심으로 다시 쓴다.
  - 직업명을 남기면 "이 유형은 이 직업과 안 맞는다"는 단정이 되고, 해당 직업을 폄하하는 표현("반복 업무", "들어 주기만")이 섞이기 쉽다. (심리학자 검토 반영)
- CTA → 지온: "일 고민, 지온과 정리해 볼까요?"

### 3.7 연애관 (`relationships.romantic`)
- `style`·`advice`를 해요체로 다시 쓴다.
  - 연인의 성별이나 연애 여부를 전제하지 않는다.
  - 신체적 묘사는 하지 않는다.
- CTA → 하랑: "관계 고민, 하랑에게 털어놓아 볼까요?"

### 3.8 궁합 미리보기 (부가, **신규** `compatPreview`)
- 잘 맞는 유형 2개 + 부딪히기 쉬운 유형 2개 (기존 `bestMatches`·`challengingMatches`)
- **신규** `compatPreview[].line`: 한 줄 설명
  - `compatibility.json`의 `summary`는 인지기능 약어투성이라 그대로 쓰지 않는다.
  - 256개 전체를 고치지 않고 미리보기 4개만 새로 쓴다.
  - **작성 규칙**: 끌림·강점 하나 + 그 조합의 `challenges` 중 하나를 반영한 작은 제안 하나. 잘 맞는 사이에도 도전 과제를 꼭 한 가지 넣는다(심리학자 검토 반영).
- 화면 라벨: 데이터의 `level`은 그대로 두고, 화면 표시만 순화한다.

  | 데이터 `level` | 화면 표시 |
  |---|---|
  | excellent, good | 잘 통하는 사이 |
  | moderate | 서로 맞춰 가는 사이 |
  | challenging, difficult | 서로 배울 게 많은 사이 |

  - 미리보기 대상 74쌍 중 moderate가 5쌍이 있다.
- **기준 데이터 (해결, 2026-10-28)**: 미리보기 대상은 `compatibility.json`에서 도출한다.
  - 도출 규칙
    - 자기 자신과의 쌍은 제외한다.
    - 점수 상위 2개 = `bestMatches`, 하위 2개 = `challengingMatches`
    - 동점이면 기존 프로필 목록에 있던 유형을 먼저, 그다음 유형 코드 알파벳순
  - 롤아웃 전에는 16유형 중 14유형에서 프로필의 `bestMatches`가 점수표 최고점과 달랐다. 점수표도 방향에 따라 점수가 다른 쌍이 13개 있었다. 정리 내역은 부록 D.1에 있다.
  - 점수를 바꾸면 이 규칙으로 `bestMatches`·`challengingMatches`와 `compatPreview`를 함께 다시 만들어야 한다.

- 고정 안내 문구: "궁합은 운명이 아니라, 서로 다른 작동 방식을 보여 주는 참고예요."
- 상세 궁합(16유형 전체)은 하랑 상담 또는 궁합 페이지로 연결한다.

### 3.9 사회생활 팁 (**신규** `socialTips`)
- 장면 3개: 직장(일) · 학교(팀플) · 모임. 각각 바로 써먹을 행동 한 가지를 쓴다.
- `relationships.friendship`의 `style`·`advice`는 작성 참고 자료로 쓴다(화면에는 직접 노출하지 않음).
- CTA → 지온: "회사·학교 사람 관계, 지온에게 물어보기"

### 3.10 닮은 유명인 (부가)
- 3~4명을 표시한다.
- 고정 문구: "성향이 닮았다고 알려진 인물이에요. 공식적으로 확인된 정보는 아니에요."
  - 데이터가 전부 `verified: false`이기 때문이다.
- **선정 기준** (2026-10-28 16유형 전체 적용, `famous-people.json` `_meta.selectionCriteria`)
  1. 널리 보도된 형사·폭력·혐오 표현 논란이 있는 인물과 현역 국내 정당 정치인은 제외한다.
  2. 화면에는 `featured: true` 4명만 표시한다. 한국 인물을 우선한다(데이터에 일본 인물은 아직 없음).
  3. 분야가 고르게 섞이도록 고른다.
  4. 새 인물은 추가하지 않는다(유형 정보가 모두 추정치이므로).
- 삭제 내역은 부록 D.2에 있다.

### 3.11 성장 한마디 (**신규** `growthMessage`)
- 1~2문장, 80자 이내. 리포트의 마지막 감정선이다.
- 톤: 격려. 과장이나 toxic positivity는 피한다.
- 아래에 기존 `growthAdvice`(해요체로 재작성)를 "작은 성장 팁"으로 붙인다.
- CTA → 다온: "성장 습관, 다온과 하나씩 만들어 볼까요?"

### 3.12 상담 연결 CTA
- **섹션 CTA** (작은 카드)
  - 문구: "{personaName}에게 물어보기" + 추천 질문 1개
  - 추천 질문은 `chatbot-prompts.json`의 해당 persona `starterQuestions`에서 고른다.
- **최종 CTA** (리포트 끝)
  - 제목: "더 깊은 이야기는 세 상담사와 나눠 보세요"
  - 3장의 카드: 이름 · 라벨 · 담당 범위 한 줄
    - 지온 · 커리어 멘토 · 진로와 회사·학교 생활 고민
    - 하랑 · 관계 상담사 · 연애와 소중한 관계 고민
    - 다온 · 자기계발 코치 · 미루기·번아웃·자존감 고민
- 면책 문구("전문 상담·진단을 대체하지 않아요")는 최종 CTA 아래에 작게 고정 표시한다.

## 4. 데이터 스키마 — `profiles.json` v2 추가·변경 필드

```jsonc
{
  "INFP": {
    // 유지: typeCode, nickname, group, groupLabel, cognitiveStack, coreTraits, statistics
    // 유지(위치만 '더 알아보기'로): introduction

    "mirror": {                                   // 신규
      "headline": "string",
      "lines": ["string", "string", "string"]     // 3~4개
    },
    "strengths": [{ "title": "string", "description": "string(재작성)" }],
    "weaknesses": [{ "title": "string(상황형)", "description": "string(재작성)", "recovery": "string(신규)" }],
    "careers": {
      "workStyle": ["string", "string", "string"],                   // 신규
      "recommended": [{ "field", "roles", "reason(다듬기)" }],
      "lessIdeal": [{ "environment(직업명 대신 환경 라벨)", "reason(환경 중심 재작성)" }]
    },
    "relationships": {
      "romantic": { "style(재작성)", "bestMatches", "challengingMatches", "advice(재작성)" },
      "friendship": { "style", "advice" }          // 유지(작성 참고용)
    },
    "compatPreview": [                             // 신규
      { "type": "ENFJ", "kind": "best | challenging", "line": "string" }
    ],
    "socialTips": [                                // 신규
      { "scene": "직장 | 학교 | 모임", "tip": "string" }
    ],
    "growthMessage": "string",                     // 신규
    "growthAdvice": [{ "area": "string", "tip": "string(재작성)" }]
  }
}
```

- **챗봇 영향**
  - 챗봇은 `strengths`·`weaknesses`·`careers`·`relationships`·`growthAdvice`를 주입한다(`chatbot-prompts.json` injectFields). 문체가 바뀌어도 동작에는 문제가 없다.

- **공통 리포트 메타**(섹션 제목·순서·CTA 문구·축 설명·궁합 라벨·고정 안내 문구)는 `data/report-sections.json`에 있다.

  - 톤 가이드 §8 패턴, 스키마·개수, 길이, 유형 간 문장 반복(오류)과 거울 문장 유사도(경고)를 검사한다.
